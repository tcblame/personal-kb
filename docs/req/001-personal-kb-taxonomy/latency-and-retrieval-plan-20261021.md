# Personal KB 延迟与误召回治理实施方案

日期：2026-10-21。状态：A/B/C 已实现，已更新 canonical WSL 安装并完成入口验收。

## 目标和当前证据

保持宽松的历史检索触发规则、单一数据根、只读检索和现有可信度分层。
减少可证明重复的检查，防止检查失败被当成可信结果，并修正查询主体被
通用词遮蔽的误召回。实现、测试、实际安装和真实任务收益分别记录。

既有计时已经安装。一条涉及编程助手对话成本的查询错误返回业务系统
“自由对话 4 秒与 96 token”的记录。一次计时样本为：入口内部 7.35 秒，
证据核验 6.54 秒，5 次记录核验、11 个证据快照、4 次记录缓存复用、
26 次原始候选访问和 128 次 Git 调用。数字为单次样本，不能当作平均值、
普遍收益或可消除的重复次数。Git 总数也包含 KB 文件自身的安全检查。

同模型同思考深度的独立对抗审阅和父 Agent 源码复核确认：

- 路径相同的不同历史快照可能需要不同 freshness，不能缓存最终结论。
- HEAD 不变不代表工作树、index、remote 配置或 linked worktree 状态不变。
- 基线版本的 `git status` 非零退出会被误当作 clean；先做独立正确性修补。
- 编程助手名称被无条件当作上下文通用词，会弱化真正的查询主体。
- 当前 `--scope-anchor` 只校验查询并写回回执，不是候选过滤器。
- 临时空目录的 closeout 成绩不能解释正式库历史收尾耗时。

### A：重复率和错误处理

仅在显式 `--timings` 下，记录固定 Git 子命令的总次数、唯一检查组合数、
重复调用数及其耗时。唯一组合区分调用目录及完整参数；
键只在进程内保存，报告不输出路径、查询、Git 参数或摘要哈希。计时使用
调用者传入的目录，不额外解析目录别名；不同别名保守地计为不同检查。
重复只是优化候选，不能直接解释为可以安全省略。

Git 冲突/状态检查非零退出和无法执行均不能成为 clean/fresh。新增隔离
故障回归，并将这项预期的错误语义修正与纯性能等价性分开验收。

### B：最小事实复用

每次检索新建上下文，结束即丢弃，不写磁盘缓存，不跨请求共享。
优先复用已解析明确 OID 的提交存在性、两个明确提交的祖先关系和
`resolved_HEAD:path` 文件 blob。缓存区分实际 worktree，逐个 snapshot
继续比较它自己的 repo、branch、commit 和 blob 期待值。

工作树、index、分支、remote 身份等可变事实第一版仍实时检查。失败结果
不作为可信事实缓存。路径定位不跨 nested repo 或 linked worktree 合并。
仅在本次重复率数据证明值得且已有完整路径解析回归后，再决定批处理；
不默认全面改用批量 status/ls-files，不只核验最终 top K。

### C：召回主体

区分“正在讨论编程助手本身”和“用编程助手处理另一个业务问题”。
主语识别只使用当前查询和可解释的字段匹配；在昂贵核验前排除仅由
通用词串联的候选，同时保留与主题吻合的通用/跨项目经验。
不把 token 设为全局黑名单，不按仓库硬隔离，不要求所有适用记录必须
字面包含某个产品名，不改变约 30% 的触发路由。新的筛选原因可计数。
`--scope-anchor` 本轮维持原契约，避免暗改既有参数语义。
显式 `--include-weak` 的宽松诊断模式可绕过新增主体筛选，普通检索保持精度门槛。

## 验收和回滚

测试一律临时数据根，并用生产保护 guard 检查 records、runtime、manifests、
retained-files 的 SHA-256、大小和 mtime。覆盖：

1. 默认 stdout、静默 closeout、退出码、receipt 与计时隐私契约。
2. Git 非零返回、执行异常、临时不可用不产生 fresh。
3. 同路径新旧 snapshot 得出不同结论；不同请求之间没有缓存复用。
4. staged/unstaged/untracked/conflicted、分支切换、remote 改动、nested repo、
   linked worktree 和含空格/特殊字符路径仍可正确判断。
5. 原查询排除业务 96 token 误命中；业务 96 token 正例仍命中；没有产品名的
   跨项目技术经验、工具只是执行角色、多主题与无明确主体的边界案例。
6. 固定语料的基线/候选比较，报告返回结果、freshness、Git 次数与耗时。
   正确性修补及有意召回修正单独列差异，不伪称全部行为完全相同。

更新前备份实际 WSL 安装文件和配置，保留机器特定替换；验证真实入口与
候选指纹一致。必要时恢复备份脚本。Windows 旧副本不作为本轮执行入口。
本轮不修改 WSL 启动/网络、持久知识记录、检索触发策略或 closeout 架构。
